# Exchange a single-use callback code for the ElderFlow session

After an External login provider redirects to ElderFlow, the backend redirects the browser to the frontend with only a short-lived, opaque, single-use completion code; the frontend immediately exchanges that code for the same ElderFlow session token issued by Local login. The code is bound to the original login transaction, expires after a few minutes, and becomes invalid after its first exchange, preventing the longer-lived ElderFlow bearer token from appearing in redirect URLs, browser history, reverse-proxy access logs, referrer data, screenshots, or copied links at the cost of one additional backend exchange request. External login transactions and hashed completion codes are kept as automatically expiring PostgreSQL records rather than process memory so callbacks survive backend restarts and work across multiple app instances; the records contain only short-lived protocol state, are consumed once, and never retain provider tokens.
