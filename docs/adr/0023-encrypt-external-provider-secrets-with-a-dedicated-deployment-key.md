# Encrypt External login provider secrets with a dedicated deployment key

External login provider configuration is managed through the web UI, but any client secret is encrypted before database storage with a dedicated deployment-provided key because the backend must decrypt that secret during token exchange. The key remains separate from session signing and Protected-text encryption, provider secrets are never returned after saving, and restoring the configuration requires both the database and the same deployment key so database backups alone do not disclose credentials. A missing or incorrect deployment key does not prevent ElderFlow from starting or affect Local login: secret-dependent provider configuration is unavailable, its login button is hidden, saving a client secret is refused, and Superadmins and IT admins receive a clear configuration diagnostic; providers configured without a client secret remain usable without the key.
