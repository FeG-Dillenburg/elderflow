# Support OpenID Connect and a constrained ChurchTools OAuth adapter

ElderFlow supports generic External login through OpenID Connect discovery with fixed `openid email` identity requirements, plus a dedicated ChurchTools OAuth adapter that derives authorization, token, and user-info endpoints from the ChurchTools installation URL and requires neither scope nor client secret. Arbitrary OAuth endpoint, scope, and claim-mapping configuration is excluded from the first implementation because OAuth alone does not standardize identity and the extra flexibility would enlarge the security and support surface without a current use case. Self-hosted OpenID Connect providers on private networks are supported deliberately: production URLs require HTTPS, while loopback, link-local, cloud-metadata, embedded-credential, unsafe redirect, and unsafe discovered-endpoint targets are rejected so private-network support does not turn provider discovery into unrestricted server-side requests.
