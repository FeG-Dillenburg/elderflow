# Link External identities by email without provisioning Users

The first successful External login links the provider identity to exactly one active ElderFlow User by normalized email: OpenID Connect requires a verified email claim, while a configured ChurchTools provider treats the email returned by its user-info endpoint as authoritative. Both adapters must also yield a stable provider subject; provider testing and login fail if ChurchTools does not supply one, and email is never used as the lasting external identity. ElderFlow never provisions or updates Users from provider profile data; every User is onboarded with and retains Local login credentials, while External login neither requires a prior Local login nor replaces the local password. After linking, ElderFlow authenticates by the provider's stable identity and never silently moves that identity when an email changes, preserving low-friction onboarding without letting external profile data control local roles or ownership.
