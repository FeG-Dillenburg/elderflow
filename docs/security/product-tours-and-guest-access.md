# Product tours and Guest Protected-text access (#81)

Issue #81 deliberately separates Protected-text readers (Superadmin, Admin, User, Guest) from Key operators (Superadmin, Admin, User). Existing backend resource permissions still determine which records can be read or changed. Guests can fetch ordinary passphrase and Content-key wrappers, register a new client epoch, revoke their own epochs, and receive authorized ciphertext. They cannot obtain recovery material, join ceremonies, rotate keys, write content, or obtain collaboration write tickets. IT admins remain excluded from both policies.

Client-epoch registration uses an insert, not an upsert: an existing epoch ID cannot be reassigned to a different user or overwritten. Revocation remains scoped to the authenticated user. Authorized Guest readers possess decryption keys in their trusted browser; this does not prevent a reader from copying already-decrypted content, and key rotation cannot revoke copies already obtained.

Tour progress is content-free, authenticated user metadata in PostgreSQL. The additive `TourProgress1720000023000` migration creates a new table without modifying existing data. The composite primary key is `(user_id, tour_id, version)`. Atomic updates preserve the first completion timestamp and completed state across manual replays and concurrent skips. Attempts and first/last start and last skip timestamps remain available. Missing rows mean unseen. The API validates tour IDs, versions, audiences, and stable step IDs and derives identity from the authenticated session.

Driver.js is presentation only. The typed frontend registry owns trusted translation keys and stable targets; no user-authored HTML reaches its popover renderer, and even translated text is HTML-escaped. Explicit login and closed-to-open dialog events are the only automatic triggers. Session restoration does not emit a login trigger. The queue checks authoritative progress at each attempt and clears pending work on identity or route changes. The first-login tour preserves the original safe return path and temporarily shows Dashboard. It suspends its overlay for unlock, and recovery aborts the attempt. Manual replay preserves completion.

The two New Topic entry points use the same form, selector targets, tour ID, and backend state. During playback, only the popover controls and requested next option can receive input. Driver owns modality while active; PrimeVue resumes modality when playback suspends or ends. Tour text and controls use English/German catalogs. Keyboard focus is contained, Escape is disabled for mandatory steps, skipped attempts remain eligible, and missing final targets never imply completion. API timeouts fail open with a localized status message.

## Verification

- PostgreSQL HTTP tests: populated-schema upgrade, identity isolation, retries, concurrent replay/skip after completion, invalid input, audience restrictions, Guest wrappers/epochs, IT-admin exclusion, recovery denial, and duplicate epoch rejection.
- UI tests: type advancement by controls and requested options; disabled unrelated interactions; Escape/retry; completed-version suppression; delayed responses across account changes and retired dialogs; overlapping-dialog queueing; German controls and focus return; actual login UI, mandatory welcome, unlock suspension/resumption, and safe return-route preservation. The production meeting adapter also has regression coverage for Guest read-only access without collaboration tickets.
- Native Chrome against `pnpm dev`: explicit login welcome, mandatory Escape, all first-login targets, successful unlock with test data, keyboard Tab containment, session refresh without login replay, and New Topic advancement including keyboard selection of Person. Finishing retained Recurring; reopening the dialog suppressed the completed tour. With the user-provided Guest session, the first-login tour completed, unlocking revealed dashboard/topic/meeting ciphertext, the completed agenda was read-only, recovery and New Topic controls were absent, and Help offered only the permitted first-login replay. Active-meeting access without collaboration tickets is covered by the UI regression test; the local browser dataset contained completed meetings.

Historical evidence documents describing Guest ciphertext exclusion predate #81 and are superseded by this policy. This file records local test evidence, not a staging deployment or an independent security certification.
